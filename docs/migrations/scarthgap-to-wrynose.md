# Scarthgap → Wrynose Migration

Tracking the migration of avocado-os from the Scarthgap LTS line to the
upcoming Wrynose Yocto release. Branch: `wrynose` (forked from
`scarthgap-avocado`).

Survey date: 2026-04-28.

---

## Survey Method

For every repo referenced under [kas/](../../kas/):

1. `git ls-remote --heads <url>` to look for a `wrynose` branch.
2. If `wrynose` exists, pin to its current head commit.
3. Otherwise, fetch `conf/layer.conf` at the latest `main`/`master`
   commit and check `LAYERSERIES_COMPAT_*` for `wrynose`.
4. If the layer declares wrynose compat, pin the kas entry to that
   commit on `master`/`main`. Otherwise leave the entry on its current
   scarthgap pin and add it to the blocked list below.

has only `2.8-avocado` (matching the previous `scarthgap-avocado` line).

custom patches we still need, fork-port them to a new `2.18-avocado`
branch and re-pin.

Same shape: previous pin was `scarthgap-avocado`, new pin is unpatched
`master`. If the avocado patches are still needed, create
`wrynose-avocado` and re-pin [kas/vendor/oe.yml](../../kas/vendor/oe.yml).

## Known Drift to Revisit

Things that work but look stale or off-pattern relative to wrynose
upstream — fix only after the build is green so we can isolate cause
of breakage.

### `nativesdk-systemd-systemctl_259.5.bb`

This is our nativesdk port of upstream `systemd-systemctl-native_259.5.bb`.
Beyond the legitimate `native` → `nativesdk` differences (class +
`--sysconfdir ${SDKPATHNATIVE}${sysconfdir_nativesdk}`), it has drifted:

- **DEPENDS uses bare names** (`libcap libxcrypt util-linux`) instead of
  nativesdk variants (`nativesdk-libcap nativesdk-util-linux`). Bare
  names will pull target builds, which is wrong for a nativesdk recipe.
  Upstream native dropped `libxcrypt` entirely; we still carry it.
- Missing `EXTRA_OEMESON += "-Dsysvinit-path= -Dsysvrcnd-path="` that
  upstream native uses to disable sysv-init paths.
- Missing `FILESEXTRAPATHS:prepend := "${THISDIR}/systemd:"` — only
  matters once we want to add nativesdk-specific patches.

(Upstream's `do_install:append` installing `systemd-sysv-install` is
documented as scheduled for removal at systemd 259, so our omission of
that one is correct, not drift.)
