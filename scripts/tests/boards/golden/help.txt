### argparse before 3.13
usage: avocado-flash [-h] [-m MACHINE] [-d DEPLOY] [-b {fwup,bmaptool,uuu}]
                     [-t TASK] [-n] [--stale-ok] [-y] [-p PORT] [-k KEYS]
                     [--key-type KEY_TYPE] [--spsdk-bin SPSDK_BIN] [--commit]
                     [--interrupt] [--ums-dev UMS_DEV]
                     [--usb-controller USB_CONTROLLER]
                     {sd,emmc,ums,fuse-srk} [device]

Write a built Avocado OS image to a board, or program its SRK fuses.

positional arguments:
  {sd,emmc,ums,fuse-srk}
  device                block device for 'sd'

options:
  -h, --help            show this help message and exit
  -m MACHINE, --machine MACHINE
                        Avocado machine (default: $MACHINE, else autodetect)
  -d DEPLOY, --deploy DEPLOY
                        deploy directory (default: autodetect)
  -b {fwup,bmaptool,uuu}, --backend {fwup,bmaptool,uuu}
  -t TASK, --task TASK  fwup task: complete (whole medium, including var) or
                        upgrade (inactive A/B slots only, var untouched)
  -n, --dry-run         print what would run; touch nothing
  --stale-ok            write even when the payload is older than the build
                        output
  -y, --assume-yes      skip the confirmation. For a board farm, not
                        interactive use
  -p PORT, --port PORT  serial console (fuse-srk)
  -k KEYS, --keys KEYS  AHAB PKI tree (fuse-srk)
  --key-type KEY_TYPE
  --spsdk-bin SPSDK_BIN
                        directory holding nxpimage/nxpcrypto
  --commit              fuse-srk: actually program the fuses (irreversible)
  --interrupt           get the board to a U-Boot prompt first, rebooting it
                        through the console if it is running Linux
  --ums-dev UMS_DEV     what U-Boot exports for 'ums' (default: mmc 1; 'mmc
                        list' names which is the SD)
  --usb-controller USB_CONTROLLER
                        USB controller index for 'ums' (default: 0)

media:
  sd        removable block device (SD card, USB stick); needs a device
  emmc      on-board eMMC over USB serial download
  ums       flash the board's own card in place. U-Boot exports it as USB mass
            storage, so the card never leaves the slot. Needs the board at a
            U-Boot prompt and a cable on the SoC's OTG port - on the FRDM-IMX93
            that is P2, not the power-only P1 or the debug P16.
  fuse-srk  program the AHAB SRK hash over the serial console. Never reachable
            from sd/emmc: flashing is repeatable, fuses are not.
  ssh-emmc  write a board's eMMC over SSH; must be the first argument and takes
            its own options (see 'avocado-flash ssh-emmc --help').
  nvme      flash a Jetson Orin Nano's NVMe in USB recovery mode; must be the
            first argument and takes its own options (see
            'avocado-flash nvme --help').

backends:
  fwup      writes the stone fwup archive. The default for 'sd' because it is the
            only backend that evaluates the manifest, so partitions marked expand
            grow to fill the medium.
  bmaptool  writes a raw .wic/.img, skipping unmapped blocks and verifying a
            SHA256 per mapped region.
  uuu       NXP serial-download protocol; the board must already be in serial
            download mode.

examples:
  avocado-flash sd /dev/sdb
  avocado-flash --machine avocado-imx93-frdm sd /dev/sdb
  avocado-flash emmc
  avocado-flash nvme --dry-run
  avocado-flash -k ~/ahab-keys fuse-srk
